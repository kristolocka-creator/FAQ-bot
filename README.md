# Rule-based чат-бот для FAQ

Простой rule-based чат-бот: загружает базу вопросов-ответов из JSON,
ищет ответ по ключевым словам и синонимам, ведёт историю диалога,
экспортирует её в CSV и логирует неизвестные вопросы.

## Структура проекта

```
src/
├── data/
│   ├── faq.json
│   └── unknown_questions.log   (создаётся автоматически)
├── support_bot.py
├── test_support_bot.py
├── demo.py
├── history.csv                 (создаётся при /export)
└── README.md
```

## Запуск

```bash
# из папки src/
pytest test_support_bot.py -v
python demo.py
```

## Формат JSON-базы

```json
{
    "вопросы": [
        {
            "question": "Как сменить пароль?",
            "answer": "Зайдите в личный кабинет → Настройки → Сменить пароль.",
            "keywords": ["пароль", "сменить", "изменить", "новый"],
            "synonyms": {
                "сменить": ["поменять", "заменить"],
                "пароль": ["код доступа"]
            }
        }
    ]
}
```

- `keywords` — обязательный список ключевых слов.
- `synonyms` — необязательный словарь: ключ — ключевое слово,
  значение — список синонимов. Синонимы участвуют в поиске наравне с `keywords`.

## Логика поиска

### Нормализация (`_normalize`)
- Приведение к нижнему регистру.
- Замена всех символов, кроме букв, цифр, пробелов, дефиса и апострофа,
  **на пробел** (чтобы не склеивать слова: `«что,другое»` → `«что другое»`).
- Дефис и апостроф сохраняются: `«что-то»`, `«don't»`.

### Токенизация (`_tokenize`)
- `re.findall(r"[a-zа-яё0-9'-]+", text.lower())` — выделяет целые токены.
- `\w` в Python 3 включает кириллицу, поэтому regex-класс покрывает и русский.

### Подсчёт очков (`_compute_score`)
- Для каждой записи FAQ заранее (при загрузке) строится множество
  нормализованных токенов из `keywords` + всех `synonyms`.
- Score = мощность пересечения множества токенов вопроса пользователя
  и множества ключевых токенов записи.
- Совпадения **только целых слов** — подстрочные совпадения не учитываются.
- Выбирается запись с максимальным score. Если score == 0 —
  возвращается заглушка.

### Tie-break
При равенстве score выбирается **первая** запись в базе (условие `score > best_score`).
Это осознанное упрощение: база упорядочена по важности, и первая запись
считается приоритетной.

## Обработка неизвестных вопросов

Если ни одна запись не набрала score > 0:
- пользователю возвращается `«Извините, я не понял вопрос. Пожалуйста, уточните.»`;
- вопрос дописывается в `data/unknown_questions.log` в формате
  `<ISO-timestamp> | <вопрос>` — для последующего расширения базы.

## Спецкоманды

| Команда    | Действие                                              |
|------------|-------------------------------------------------------|
| `/help`    | список доступных команд                               |
| `/history` | последние 5 пар «вопрос — ответ»                      |
| `/export`  | сохраняет историю в `history.csv`                     |

Спецкоманды обрабатываются до поиска и **не записываются** в историю.

## Пример диалога

```
USER: Как поменять пароль?
BOT : Зайдите в личный кабинет → Настройки → Сменить пароль.

USER: Хочу вернуть товар
BOT : Возврат оформляется в разделе Мои заказы в течение 14 дней.

USER: Как приготовить борщ?
BOT : Извините, я не понял вопрос. Пожалуйста, уточните.

USER: /history
1. Q: Как поменять пароль?
   A: Зайдите в личный кабинет → Настройки → Сменить пароль.
...

USER: /export
История экспортирована в history.csv
```

## Ограничения rule-based подхода

- **Опечатки** не распознаются: `«пароль»` ≠ `«парол»` → уйдёт в лог.
  Улучшение: `difflib.SequenceMatcher` / расстояние Левенштейна.
- **Морфология**: `«пароли»` не совпадёт с `«пароль»` без явного синонима.
  Улучшение: простой стемминг или расширение синонимов.
- **Нет контекста**: каждый вопрос обрабатывается независимо.
- **Ручное ведение базы**: новые синонимы и вопросы добавляются вручную.
- **Коллизии ключевых слов** при росте базы: нужно взвешивание (TF-IDF).

### Rule-based vs LLM
Rule-based: дёшево, быстро, предсказуемо, работает offline.
LLM: гибче, но дорого, медленно, возможны галлюцинации.
Разумный гибрид: rule-based впереди, LLM — как fallback для неизвестных запросов.
